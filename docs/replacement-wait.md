# 초기화와 교체 대기

초기화나 같은 사용자의 재생성 요청은 이전 인스턴스가 CLEANED가 된 뒤 새 실행을 예약합니다
이전 실행 ID는 V20의 replaced_instance_id에 저장합니다 기존 행은 null로 남습니다

브로커가 후보 없음이나 확실한 용량 부족을 반환하면 30초 간격으로 다시 확인합니다
기존 실행을 지워도 다음 용량 관측 전까지는 후보가 보이지 않을 수 있기 때문입니다
브로커의 시계 오차 방어와 예약 차감 규칙은 변경하지 않습니다

대기 상한은 scheduler.operation.replacement-wait-timeout으로 설정하며 기본값은 10분입니다
환경변수는 SCHEDULER_OPERATION_REPLACEMENT_WAIT_TIMEOUT입니다
기존 expires_at과 hard_expires_at이 먼저 오면 그 시각에 대기를 끝냅니다 초기화로 사용 시간이 늘어나지 않습니다
기한과 다음 확인 시각은 DB에 남아 재시작해도 이어집니다

기한을 넘기면 RESOURCE_UNAVAILABLE로 실패하고 새 런타임 생성을 요청하지 않습니다
예약 응답을 기다리다가 기한을 넘기면 받은 예약을 반납합니다
이전 실행의 정리가 실패하면 새 실행도 진행하지 않으며 기존 정리 상태는 유지합니다
인증 오류나 브로커 연결 장애는 기존 broker-retry-limit을 따릅니다

일반 신규 생성의 재시도 정책은 변경하지 않습니다
오래된 행의 교체 관계는 추측해서 채우지 않습니다
